# PPG_TIMING_DEV1：开发集时间诊断

2026-10-19，执行前固定本说明。仅S1–S5的10份静坐/步行记录；不读取S6–S15评分，不更新PPG_CAPTURE1及疾病结果。

1. 复用已完成的PPG_CAPTURE1峰值缓存并核对哈希。不增加检测器、不改质量门控。
2. 比较旧范围0–0.6秒与诊断范围−1.5至+1.5秒，间隔0.01秒；正值表示PPG峰减去该偏移后与ECG对应。每记录仅首120秒选最大匹配数；同分先接近0.2秒，再较小值。固定评分核心4–26秒，确保两范围具有相同参考分母及足够边界。
3. 将首120秒选出的偏移冻结后应用到剩余开发数据；另外计算每个120秒块的最优偏移，只用于检查时间稳定性，不用于修正成绩。保留离最佳偏移至少0.3秒的竞争峰；周期性信号存在整搏混淆，不能把最大匹配偏移当成设备物理时钟。
4. 合成非等间距心搏，验证正负已知偏移的恢复；用不同脉宽的合成PPG比较原始峰与因果0.5–5Hz三阶滤波峰，测量形态相关位移。这是软件诊断，不是人体信号准确率。
5. 真实开发信号使用同一现有峰值规则比较未滤波与因果滤波峰的近邻对应（±250ms），报告匹配率与中位位移；仅为滤波敏感性，不是专家标注验证。

公共输出仅两活动与总体汇总、复核计数、方法和源哈希。逐记录、逐窗和候选偏移曲线保存在outputs/ppg_timing_dev_v1。下一协议必须考虑校准稳定性和整搏混淆；扩大搜索后提高的参考辅助F1不能宣称检测器性能改善，更不能宣称低血糖效能提升。

参考：[PPG-beats对齐接口](https://ppg-beats.readthedocs.io/en/stable/functions/align_ppg_ecg_beats/)明确区分最大偏移、步长、容差和分窗；GPL实现未复制。[Empatica BVP说明](https://www.empatica.com/blog/decoding-wearable-sensor-signals-what-to-expect-from-your-e4-data/)说明64Hz和专有组合处理，不据此假定一个固定处理延迟。
