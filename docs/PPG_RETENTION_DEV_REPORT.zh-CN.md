# PPG质量筛选：精度提高付出了多少覆盖代价？

2026-10-20 · PPG_RETENTION_DEV1 · 已见开发集探索

结论：现有SQI的简单整窗筛选不宜启用。预设q50规则让输出PPV按人平均提高7.71个百分点，但全参考敏感度下降23.58个百分点、PPI覆盖下降18.57个百分点、核心评分时间覆盖下降28.26个百分点。较高输出精度来自更少的输出，尚不能作为总体找搏改善，更不能用来宣称低血糖检测提升。

## 固定协议

运行前冻结d0fba77，见[METHOD_PPG_RETENTION_DEV1](METHOD_PPG_RETENTION_DEV1.zh-CN.md)。前次因自动审批额度限制未能执行；本次恢复后首次运行，没有重复主实验。仅原5开发人、10记录；首120秒每记录4个窗的SQI等权分位数q25/q50/q75用于尾段，外加不筛选baseline共4路。SQI>=阈值保留整窗，否则该窗候选不输出。全部工作点预先固定、全部报告，无尾段选阈值，q50只是预设区间对照。

沿用上升沿候选与首120秒固定参考辅助偏移。171个尾窗采用同一参考时间核心[4,26)；所有参考搏和参考相邻间期始终留在分母。拒绝窗中的原TP计为新增FN，原FP不再输出；不跨拒绝窗拼接间期。保留子集的输出PPV与全参考敏感度分别报告，零输出PPV为空而非100%。本轮实际没有零输出记录。

参考未匹配并非人工伪迹真值；偏移歧义仍存在。首120秒只有4个SQI校准值，阈值稳定性未知。SQI依赖完整30秒窗，未验证在线时延。这是5人已见开发集探索，不是外部或临床验证。

## 验收与决策

独立复算30个校准阈值、171尾窗匹配/PPI、40个记录工作点和4个按人区间通过。每路原参考分母守恒，保留集合按q阈值嵌套，baseline逐记录精确复现PPG_UPSTROKE_DEV1；零输出控制验证PPV为空、召回/F1为0。复核使用既有独立searchsorted匹配与PPI计数器，代码哈希见[验收JSON](acceptance/PPG_RETENTION_DEV1.json)。逐记录阈值和输出仍只在本地ignored目录。

不采用当前SQI分位数整窗拒绝作为改进方案，也不继续扩大这些阈值网格。下一步回到PPG候选本身：先冻结候选级局部模板一致性与相邻间期一致性定义，对照现有窗级SQI，训练/校准段内确定规则，完整尾段仅评价。先证明能区分错误且保留有效搏动，再考虑质量筛选；仍不切换疾病融合模型或临床终点。

本轮没有新的疾病事件召回、误报/参考人日、及时性或疾病PPV结果。原V1–V5及PPG对照失败证据保持，工程验收不等于临床达标。
