# PPG开发集时间诊断：对齐方式影响了匹配成绩

2026-10-19。协议在执行前以557ea1b提交。仅使用S1–S5，10份活动记录、211个30秒窗口；未重跑疾病模型，未评分其余受试者。

## 已完成什么

固定原峰值检测器，以每记录首120秒选择共享偏移，再冻结应用到剩余开发时间。只比较旧范围0–0.6秒与诊断范围−1.5至+1.5秒；两者都使用4–26秒核心，参考分母一致。

|开发活动|旧范围校准后的尾段F1|扩大范围校准后的尾段F1|偏移落在旧范围外|
|---|---:|---:|---:|
|静坐，5份|41.12%|58.71%|3/5|
|步行，5份|38.18%|47.60%|5/5|

先等权汇总每人的两活动，再对5人配对bootstrap：F1差+13.50个百分点，探索性95%区间[+1.14,+27.29]个百分点。这是**对齐敏感性**，不是新检测器胜出、无参考部署效果或低血糖效果。校准用到了ECG参考，既有测试已被查看。本诊断评分核心不同，不能把这里数字与PPG_CAPTURE1留出47.77%直接相减。

## 还缺什么

- 5份步行记录中，2份存在距离最佳偏移至少0.3秒、匹配数仍达到最佳95%的竞争偏移。周期性心搏可能错配到相邻一搏；最大匹配偏移不是物理时钟证据。
- 校准后各完整120秒块最优偏移相对初始值的绝对变化中位数，静坐80ms、步行90ms。它混合时钟、脉搏传导、波形变化与伪影，不能归因于单一因素；这些分块偏移没有用于修改尾段成绩。
- 合成非等间隔心搏的四个已知正/负偏移正确恢复。三种高斯脉宽经现有因果滤波后，峰值中位移动62.5、31.25、0ms，说明滤波不存在通用的单一峰值延迟。
- 真实开发数据未滤波/滤波峰的±250ms对应中位位移：静坐−187.5ms、步行+46.875ms；平均对应比例93.85%/90.73%。这不是物理传导时间，匹配也可能跨峰；没有手工PPG基准，不能认定该位移就是应扣除的设备延迟。

## 下一步

1. 保持当前两种检测器不变，在开发集检查整搏混淆、峰/上升沿位置以及不同校准段的稳定性。把歧义记录明确报告，不以删记录提高总分。
2. 冻结明确的参考辅助对齐协议后，才重新评价同队列信号子任务；所有后续修改标记探索性。部署算法仍只能读PPG，不加入ECG参考输入。
3. 暂不回到低血糖分类训练。V5的1/30及粗特征3/30结果继续保留；本次没有新的低血糖命中或误报结果。

## 复核、覆盖与来源

20个校准选择、20组尾段TP/FN/FP通过独立searchsorted实现复核；原审计用动态规划复核211窗的一对一匹配数量。两范围同参考分母，不做SQI拒绝；首120秒校准、每30秒只评分22秒、残余尾窗不评分。评分核心占校准后原始时间的活动内记录均值为静坐73.08%、步行70.73%。这不是PhysioCGM的覆盖变化，也不能把有评分窗口称作100%时间覆盖。本轮只检查偏移敏感性，不更改覆盖目标。

运行`scripts/audit_ppg_timing_dev.py`生成本地明细（拒绝覆盖已有输出），随后运行`scripts/verify_ppg_timing_dev.py`独立复算。公共汇总为`docs/acceptance/PPG_TIMING_DEV1.json`，逐记录偏移与结果仅本地`outputs/ppg_timing_dev_v1`。来源和许可沿用PPG-DaLiA审计，未复制外部算法实现。

[PPG-beats对齐接口](https://ppg-beats.readthedocs.io/en/stable/functions/align_ppg_ecg_beats/)区分最大偏移、步长、容差与分窗。[Empatica说明](https://www.empatica.com/blog/decoding-wearable-sensor-signals-what-to-expect-from-your-e4-data/)指出BVP是专有算法组合的64Hz信号；该页没有提供可直接用于本数据的固定处理延迟。这些来源支持分开审计对齐与检测，而不支持按最高F1认定物理同步。
